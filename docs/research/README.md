## Applicability to the MVP

- The 0.5.0 transition research records temperature writes with the native preview flag kept enabled for short changes, and temperature writes with occasional brief preview activation for gradual changes. Brief activation asks Windows to apply the stored temperature. The research also covers explicit cleanup and one Night Light handle reused throughout the process. Its startup timestamp margin advances the first successful settings-write timestamp at least 699 seconds beyond the stored timestamp. This native flag differs from Circadia's schedule Preview playback. Circadia does not move timestamps backward, because the upstream probe found that temperature changes after a timestamp rewind were ignored, consistent with Windows ignoring timestamps at or below an inferred highest applied value. The same document records the watcher and snapshot contracts that observation and recovery use. Source findings and upstream display observations have separate limits. Controller integration and supported-host visual behavior remain implementation and release checks. The superseded 0.4.0 contract, runtime, cadence, and timestamp research remains in Git history at commit `b3a3291`, and its probe source at commit `fb483b4`.
- The f.lux comparison supplies interaction references. Circadia defines its own manual Wake and Bedtime clocks, Daytime ≥ Morning/Evening ≥ Sleep temperatures in kelvin, optional solar targets, transitions that finish by each target, and executable matching. It does not infer Bedtime from f.lux's approximate nine-hour convention.
- The Windows clock research covers skipped/repeated times, elapsed interpolation, half-hour changes, and selected year boundaries. The combined investigation records actual host time-zone and daylight-adjustment changes. The active [Windows clock probe](../../probes/windows-clock/README.md) retains conversion tests and the separately invoked host-setting exercise. Its omission and first-occurrence fixtures do not implement the spec's elapsed-interval adjustment of Wake and Bedtime occurrences. [Clock-change intervals](clock-change-intervals.md) distinguishes that policy from the recorded conversion evidence. The application's Rust schedule tests are separate from these probe results.
- The recorded Reactor checks verify graph controls, pointer interaction at 100% scaling, settings close/reopen, a native file picker for executables, and foreground lookup. The retained probe's fixed test times and point editor differ from the generated temperature schedule. Native settings validation, selection of dated Sunrise/Sunset occurrences for schedule targets, and Preview require application verification. Current Preview starts at the current instant and ends at tomorrow's matching local clock, compressed into 1–60 seconds. The pinned UI probe does not verify this playback or how unsaved edits affect control through Save, Discard, and settings closure. The compatibility assessment supplies a dependency-based Windows 11 build 22000 floor; minimum-build execution remains a release check.
- The architecture research supports the selected single Reactor process. The [application tools](../../tools/README.md) separately check resource use and activation through real Windows tray input. Broader display scaling and accessibility remain release checks.
- Session-ending documentation and pinned source support best-effort cleanup in the same process. Actual notification delivery, cleanup during Windows teardown, and the next sign-in's Night Light state remain unverified. Startup can prepare an inactive temperature before enabling Night Light; optical absence of a transient tint is not established. The spec does not adopt the research's direct-enable option: startup prepares 6500 K before enabling Night Light and then runs a 1000 ms fade to the current target. Current exit independently clears native preview through the settings registry record and turns Night Light off through the separate state record. Failure of one does not skip the other.
- Suspend/resume documentation supports current-time reevaluation and separate treatment of timer delivery, elapsed suppression duration, and native output. Windows 11 event ordering and visible Night Light restoration have not been exercised through actual power-state transitions. Reapplying the current temperature after resume even when storage matches is a product requirement, not evidence that Windows always loses its display transform.

## Solar evidence and archived scheduling models

The local solar comparison supports the MVP's optional solar calculation. It verifies zero and repeated event counts and agreement with independent references for the recorded fixtures. The Windows location experiment supports explicit coordinate acquisition on its tested host; denied permission, disabled services, cancellation, and production integration remain application checks.

The archived scheduling algorithm adjusts Morning/Evening reference times, chosen from sunrise/sunset or backup clocks, to preserve the order of points placed at offsets from them. A separate editing experiment searches for offsets and positions that place an inserted or dragged point at the requested time while preserving the dated order of other points. These experiments use a broader editing model than the generated three-temperature schedule. Their backup clocks, movable reference times, and arbitrary offsets are not MVP requirements. The recorded results describe that tested model; they do not establish the current rules for selecting Sunrise/Sunset occurrences or generating transitions.

City/address lookup and automatic fullscreen detection remain deferred. Their provider comparisons and detection experiments do not add MVP requirements.

The [source archive](archives/README.md) preserves the solar calculator, scheduling and editing algorithms described above, combined solar harness, published Reactor comparison, and location code. Run those experiments from an extracted snapshot. The active [probe index](../../probes/README.md) lists the pinned Reactor, Windows clock, and solar-timing probes.
