# Settings design support in Windows Reactor

At windows-rs `ebc5a99`, Windows Reactor (the Rust WinUI 3 library that Circadia uses for its settings window and tray) supports most of the redesigned settings window directly: `NavigationView`, `Expander`, `ToggleSwitch`, `CheckBox`, `HyperlinkButton`, `ContentDialog`, `Slider`, `NumberBox` with a configurable step, `InfoBar`, `ProgressRing`, `ProgressBar`, SVG `Image` sources, a `TitleBar` with an icon and a tall height, and live-region announcements. It has no gradient or dashed brush, no `TimePicker` selected-time property, no secondary text, tertiary text, or divider theme brush, no `InfoBadge` glyph, no action content in `InfoBar`, no contrast-theme state, no blend effect, no `FlowDirection` or `Language` property, and no checked, bold, or two-line tray menu items.

The selected approaches:

- Draw the graph fill, curve, and slider gradient strips with the `windows-canvas` Direct2D library, while XAML draws labels, gridlines, event lines, and chips.
- Replace `TimePicker` with a segmented button that opens a flyout of lists.
- Use fixed secondary colors per light and dark theme, and Windows high-contrast system colors in contrast themes.
- Mark checked tray items with a text check mark.
- Draw no Preview tint.

Nothing in this document was rendered. A rendering probe that has not been built yet will verify appearance in dark, light, and a contrast theme at 100%, 150%, and 200% scaling, measure `windows-canvas` memory, and exercise the time-picker flyout and pseudo-localized text.

## Decision this informs

Circadia's settings redesign follows WinUI 3 and the Windows Settings app, but Circadia declares its interface through Reactor's Rust API. Each design element needs a Reactor control that exposes the needed properties, a composition of exposed controls, or an approved simplification. The product decisions settled on 2026-10-23 selected an approach for each gap. This document records the support at the current reference pin and the selected approach, so that the new pages use the selected controls from their first version. The [Windows Reactor UI research](windows-reactor-ui.md) records the tracking policy, the Reactor changes since the previous pin, and the [failure policy](windows-reactor-ui.md#failure-policy), under which invalid declarations, internal bugs, and failed native calls after startup end the process; the [interface spec](../specs/interface.md) states the required behavior.

## Evidence boundaries

**Observed in windows-rs `ebc5a99`:** The support column comes from Reactor's public declarations, generated declarations, native hosting code, and a `cargo doc -p windows-reactor --no-deps` build. A row states a difference from `722f202` only where one exists. Source inspection establishes that a property or composition can be declared. It does not establish how the result looks, how it behaves under input or a screen reader, or what it costs in memory. Circadia's code compiled and passed Clippy against `ebc5a99` with only the `rev` values of `windows-reactor`, `windows-window`, and `windows-reactor-setup` changed; no window was rendered for this document.

The pane header has the phase art, "Circadia", and a status line. The pages are Schedule, App suppression, Transitions, and General, so the built-in Settings item can be hidden with `is_settings_visible(false)`. |
| `SettingsCard` and `SettingsExpander` | Not declared; they are Windows Community Toolkit controls, not WinUI 3 controls. `Expander` exposes `header`, `content`, `is_expanded`, `on_is_expanded_changed`, `horizontal_content_alignment`, and `resource_overrides`. | No card control. | Build cards from `Border` with the `CardBackground` and `CardStroke` theme brushes, as the current window does. Use `Expander` for expandable cards such as "Follow sunrise and sunset" and "Never suppress". |
| `ToggleSwitch`, `CheckBox`, `HyperlinkButton`, and `ContentDialog` | All declared. `ContentDialog` exposes a title, content, three button texts, `default_button`, both button enable flags, `is_open`, and `on_closed`. Pull request 5160 makes dialogs follow the window theme, including changes while open, and stops the panic when a window closes with a dialog open. | None found. | Use them directly. Supply `ToggleSwitch` `on_content` and `off_content` so that its text comes from Circadia's translations. |
| Temperature `Slider` with a warm-to-cool gradient track | `Slider` exposes `minimum`, `maximum`, `value`, `step_frequency`, `orientation`, `header`, and `on_value_changed`. It has no `resource_overrides`, and `ResourceValue` holds only a color, thickness, or corner radius. | The track cannot be restyled. | Keep the native `Slider` and draw the gradient as a separate strip with `windows-canvas`. |
| Temperature `NumberBox` with step 10 and a "K" suffix | `NumberBox` exposes `minimum`, `maximum`, `value` (`Option<f64>`), `small_change`, `spin_button_placement_mode`, `header`, and `on_value_changed`. It has no `LargeChange`, `NumberFormatter`, `ValidationMode`, `PlaceholderText`, or `Text`. `722f202` exposes `small_change` too; published 0.100.0 does not. | No suffix or formatter. WinUI clamps a typed value to the range but does not round it to `SmallChange` (WinUI `NumberBox.cpp` at `2b337b4`). | Declare `small_change(10.0)`, round a committed value to 10 K in Circadia's message handler (the settings component's `update` method), and show "K" in a separate `TextBlock`. The value applies on commit, which is the only time `NumberBox` reports one; see [text input events](windows-reactor-ui.md#text-input-events). |
| Wake time and Bedtime `TimePicker`s | `TimePicker` exposes `minute_increment`, `clock_identifier`, `header`, `is_enabled`, and `on_time_changed`. | No selected-time property, so the picker cannot show a saved time. | A segmented button with hour, minute, and an AM/PM segment that appears only in regions with a 12-hour clock. The button opens a flyout with scrolling lists and Accept and Cancel. Ask upstream for a selected-time property. The controls this needs are in the next section. |
| Gradient fill under the graph curve | `Brush` is either `Theme(ThemeBrush)` or `Solid(Color)`. `windows-canvas` with its `reactor` feature provides `canvas(...)` views with `create_linear_gradient` and `create_radial_gradient`. `ElementRef<Image>::request_set_native_source` and `ElementRef<Grid>::request_set_child_visual` attach native image sources and composition visuals. These routes exist at `722f202` too. | No gradient brush in XAML declarations. A `windows-canvas` view or a composition visual creates a Direct3D device. | `windows-canvas` draws the fill under the curve, colored by each hour's temperature, and the curve itself. XAML draws gridlines every 3 hours with hour labels, dashed event lines, event chips, and the now line and dot. More elements can move into the canvas if needed. Measure the canvas's memory before relying on it. |
| Theme resource brushes | `ThemeBrush` has eight variants: `Accent`, `AccentText`, `PrimaryText`, `SolidBackground`, `CardBackground`, `CardStroke`, `SystemCritical`, and `SystemCriticalBackground`. Published 0.100.0 and `722f202` declare the same eight. | No secondary text, tertiary text, or divider brush. `Opacity` on `PrimaryText` approximates them but lowers contrast in contrast themes. | Use fixed secondary text, tertiary text, and divider colors per light and dark theme, copied from WinUI's values. In contrast themes, use the Windows high-contrast system colors instead. |
| Title and BodyStrong text styles | `TextBlock` exposes `font_size`, `font_weight`, `font_family`, `line_height`, and `character_spacing`. The last three are new since `722f202` (pull request 5158). | No named text styles. | Set size, weight, and line height explicitly for each style. |
| Dashed event lines | `Line` exposes `stroke`, `stroke_thickness`, `x1`, `y1`, `x2`, and `y2`. It has no dash array. `windows-canvas` `create_stroke_style` accepts a dash style. | No dash pattern in XAML. | Draw each dashed event line in XAML as short line segments. If event lines move into the canvas, use a canvas dash style. |
| Phase art | `Image` exposes `source_svg`, `source_file`, `source_data`, and `source`. | None found. | Load the per-theme SVG art and swap it on theme change. |
| Suppressed `InfoBadge` with a timer or app-window glyph | `InfoBadge` exposes only `value`, a number. | No glyph content. | Overlay a glyph (`FontIcon` or `Image`) on the phase art inside a `Grid`, styled like an `InfoBadge`. |
| Ramp `ProgressRing` and Preview `ProgressBar` | `ProgressRing` exposes `minimum`, `maximum`, `value`, `is_indeterminate`, and `is_active`. `ProgressBar` exposes the same plus `show_error` and `show_paused`. | None found. | Use them directly; lay the determinate ring over the phase art during a ramp. |
| Banners with actions, such as "Go to <page>", Retry, and "Open folder" | `InfoBar` exposes `title`, `message`, `severity`, `is_open`, `is_closable`, and `on_closed`. | No action button or custom content. | Place the action buttons next to the `InfoBar`. Announce banner changes to screen readers through a live region (next row). |
| Screen-reader announcements | `automation_live_setting` (`Off`, `Polite`, `Assertive`), `automation_help_text`, and `automation_full_description` on every element; Reactor raises `LiveRegionChanged` when a live region's text changes. `ElementRef::request_notification` raises a UI Automation notification; elements without an automation peer, such as `Grid`, report `IntegrationError::Native`. All are new since `722f202` (pull request 5170). | None found. | Mark banner and status text as live regions so that changes are announced. |
| 48 px title bar with a 16 px icon and "Circadia" | `TitleBar` exposes `title`, `subtitle`, `icon` (any `Icon`: symbol, font glyph, bitmap URI, image from a file, data, or SVG, or path), `preferred_height(WindowTitleBarHeight::Tall)`, `content`, `left_header`, and `right_header`. `window_frame`, which the current window uses, creates a `TitleBar` with only a title. Pull request 5127 fixes client sizing with custom title bars. | Microsoft documents `Tall` only as taller than the standard height based on system metrics, not as 48 px. | Declare the `TitleBar` directly with its icon and `preferred_height(Tall)` instead of calling `window_frame`. Measure the resulting height. |
| Light, dark, and contrast themes | `on_color_scheme` reports `ColorScheme::Light` or `ColorScheme::Dark`. | No contrast-theme state. | Detect high contrast outside Reactor with `SystemParametersInfo` and `SPI_GETHIGHCONTRAST`, and switch to the high-contrast colors and art. |
| Preview multiply tint over the window | No blend mode in Reactor. The `windows-composition` wrapper exposes color, nine-grid, and surface brushes, but no effect or composite-mode wrapper. | No route to a true multiply blend over XAML content was found. | Draw no tint. Circadia changes screen color only through Night Light; during Preview, the graph's now dot moves and the button reads Stop. |
| Right-to-left layout and per-control language | No public `FlowDirection` or `Language` property; only Reactor's internal bindings mention them. | Right-to-left layout is not possible through Reactor. | Right-to-left languages are out of scope for the first release. Ask upstream for both properties. [Localizing Circadia's interface](localization.md) records the evidence. |
| Controls or properties that Reactor does not declare | `ElementRef` offers only typed requests: focus, UI Automation notification, swap chain, native image source, composition child visual on `Grid`, and WebView2. `WindowHandle::as_raw` returns the window handle only. | No general access to the underlying WinUI element. | Each missing feature needs an upstream change or one of the workarounds in this table. |
| Tray menu | `MenuItem` has three variants: `Item` (key, label, enabled), `Separator`, and `Submenu`. `Menu::new(items, callback)` has no opening callback, and replacing menu content closes an open menu. | No checked state, icon, bold default item, or secondary text. ## Time-picker flyout

**Observed in windows-rs `ebc5a99`:** `FlyoutExt::flyout_with` attaches a `Flyout` with arbitrary content and a `FlyoutPlacement` to a view. The native host attaches it only to a `Button` or a `SplitButton`; any other target is an invalid object. The public `Flyout` declares content and placement only: it has no open state, no opening or closing callback, and no programmatic close. When a render removes the attachment, Reactor clears the flyout's content and the button's `Flyout` property; the code path does not call `Hide` on a plain flyout, although it does for menu flyouts. `ListView` exposes `selection_mode`, `selected_index`, `items`, and `on_selection_changed`; `ListBox` exposes `items`, `keyed_items`, and `on_selected_tag_changed` without a selected-index property. `ScrollViewer`, `RepeatButton`, `DropDownButton`, and `SplitButton` are declared. `TeachingTip` exposes `is_open`, light dismiss, action and close button text, and `on_closed`, but no content.

The following is inference, not observation. A `Button` whose content shows the hour, minute, and AM/PM segments can open a `Flyout` that holds one `ListView` per segment and Accept and Cancel buttons. Light dismiss closes the flyout without a declared state. Whether Accept and Cancel can close it, for example by removing the attachment in the next render, and whether a `ListView` scrolls its selected item into view when the flyout opens, are not established by source inspection; the rendering probe must exercise both.

## Alternatives compared

| Gap | Options compared | Selected | Criteria that separate them |
| :-- | :-- | :-- | :-- |
| Graph fill and slider gradient | Sampled XAML `Rectangle` strips (the archived probe used 220 one-pixel rectangles); a `windows-canvas` view; a composition visual with a canvas-drawn surface | `windows-canvas` for the fill, the curve, and the slider strips | Gradient fidelity and element count favor the canvas. The canvas and the composition visual each add a Direct3D device, so memory use while running decides whether the canvas stays. Sampled rectangles remain the fallback. |
| Time entry | `TimePicker` that cannot show a saved time; validated `HH:mm` text fields; a segmented button with a flyout of lists | Segmented button with a flyout | Only the text fields and the segmented button show a saved time. The segmented button follows the regional 12-hour or 24-hour clock without free-text input. Closing the flyout from Accept and Cancel is unverified. |
| Secondary text, tertiary text, and dividers | `PrimaryText` with reduced `Opacity`; fixed colors copied from WinUI per theme; an upstream brush request | Fixed colors, with high-contrast system colors in contrast themes | Reduced opacity lowers contrast in contrast themes. Fixed colors do not follow later WinUI palette changes. |
| Preview tint | A translucent overlay; a canvas-drawn composition surface; no tint | No tint | Circadia changes screen color only through Night Light, so it draws no overlay or simulated tint. |
| Checked tray items | A text check mark in the label; a submenu per app; an upstream toggle item | Text check mark, with an upstream request | A text label needs no Reactor change. A submenu adds a level to a frequent action. Toggle items do not exist at `ebc5a99`. |

## Recommendation

Build the redesigned pages with the controls and workarounds in the table above at `ebc5a99`. Before the implementation commits to `windows-canvas` and the flyout-based time picker, run the rendering probe described below. If the canvas's memory cost is unacceptable, draw the gradients with sampled rectangles. If the flyout cannot be closed from Accept and Cancel, rely on light dismiss with an explicit apply step or use a different container. Recheck each row at the next pin bump, because a Reactor change can replace a workaround.

## Rendering probe and outstanding evidence

The planned rendering probe at `probes/windows-reactor/settings-design/` does not exist yet. It will render each page and dialog with the selected controls and fixture data, and compare screenshots with the original design mockups, which are not stored in the repository; screenshots stay out of version control. It will produce the following evidence, none of which is available now:

- Rendering in the dark theme, the light theme, and a contrast theme at 100%, 150%, and 200% display scaling, including the fixed secondary colors, the high-contrast system colors, and the phase art.
- Memory use of the `windows-canvas` graph and slider strips, compared with sampled rectangles, measured before the settings window first opens, while it is open, and after it closes.
- The time-picker flyout: opening from each segment, list scrolling and selection, Accept and Cancel closing the flyout, keyboard use, and the AM/PM segment in a 12-hour and a 24-hour region.
- Pseudo-localized text in labels, cards, the navigation pane, the four-column event row, dialogs, and tray items, without clipping at each scaling level.
- The height of the `Tall` title bar and the 16 px icon at each scaling level.
- Rendering of the text check mark and the disabled caption in the native tray menu.
- Screen-reader announcements from live-region banners and status text.

## Gaps

These uncertainties could change a selected approach:

- `windows-canvas` memory cost. A cost that conflicts with the spec's resource target for memory use while running ([constraints](../specs/SPEC.md#purpose-and-scope)) moves the gradients back to sampled rectangles. The probe's memory measurement settles it.
- Closing the time-picker flyout from Accept and Cancel. If no declared route closes it, the picker needs a different interaction or container. The probe settles it.
- Whether fixed secondary colors match WinUI closely enough in both themes, and whether the high-contrast system colors keep every element visible. The probe's screenshots settle it.

These are implementation and release checks:

- Keyboard and Narrator use of every page, including focus order and the graph's accessible description.
- Explorer restart with the tray menu open, under the failure policy recorded in [Windows Reactor UI support](windows-reactor-ui.md#failure-policy).
- Clean-machine deployment of the generated `.ico` with the self-contained runtime.
